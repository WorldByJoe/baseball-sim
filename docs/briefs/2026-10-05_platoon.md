# Brief: the platoon split has the wrong sign · 2026-10-05

For a local Fable session on Joe's Mac, branch `platoon`, working copy `/Users/joevonfischer/bsim-wt/platoon`. Read
`docs/briefs/2026-10-05_parallel_rules.md` first: it sets where you work, how to run things and the rules.

## Why

**In the model, batters do better against a pitcher of their own hand; in the league they do worse.** The bug audit's
`headless/mirror_check.js` drew the same men with both hands, each mirror pair on the same dice (CALIBRATION.md,
"Bug audit", the paragraph "Mirrors and signs"):

| | model | league |
|---|---|---|
| wOBA, same-side minus opposite-side | +.013 to +.030 | -.020 to -.030 |
| K%, same-side minus opposite-side | -.009 to -.022 | higher same-side |
| BB% | higher same-side | lower same-side |

The audit found every hand-dependent line of code symmetric and the sign conventions right, so this is a missing or
wrong mechanism, not a flipped sign. Two other wrong-signed results probably share the root:

- K% against release height: +.16 in the model, -.22 in the league (lower releases strike out more);
- BB% against arm angle: near 0 in the model, +.20 in the league.

**It matters most for the next project:** Joe wants to forecast the 2026 playoffs, where managers live on platoon
matchups (left-handed relievers, pinch-hitters). A wrong-signed split misprices every one of them.

## What to do

### 1. Measure the league's split, component by component

From `statcast/raw/pitches/2025/` (42 days; `statcast/swing_geometry.py`'s `load()` reads them; the scripts in
`statcast/` show the patterns). Same-side against opposite-side, for right- and left-handed batters separately:

- the outcome line: wOBA, K%, BB%, xwOBA on contact, exit speed, launch angle;
- the plate discipline: swing, chase, zone contact, whiff per swing, called strikes;
- by pitch type (four-seam, sinker, cutter, slider, sweeper, curveball, changeup, splitter) and by location;
- the pitch mix and the locations each pitch type is aimed at, by platoon.

**Control for who.** Left-handed batters see more right-handed pitchers, managers choose same-side matchups for their
best relievers, and weak hitters are hidden from them. Compare each batter and each pitcher with himself (within-player
splits, or a model with player effects), and report how much of the raw split survives.

### 2. Measure the model the same way

Extend `mirror_check.js` or write a probe, so the model's split comes apart along the same components and pitch types.
Find which components and which pitch types carry the wrong sign.

### 3. Explain it

Find what gives the model's same-side batter the edge. Candidates, none tested:

- **The pitch mix and aim by platoon.** League pitchers throw sliders and sweepers to same-side batters and
  changeups and splitters to opposite-side ones. If the model's sliders play worse than the league's relative to its
  changeups, the mix alone could flip the sign. Check how the model chooses pitch and aim by the batter's side
  (`PLAN_LOC`, the plan code near "same-side hitter" in `bb_engine.js`).
- **Seeing the release.** A same-side release comes from behind the batter's front shoulder; the model's batter reads
  every release point equally well. The audit's suspect (PL): a later or noisier commit point by platoon.
- **Movement relative to the batter.** Same-side breaking balls break away from him, onto the part of the bat that
  reaching makes slow (`BAT_LOC`, engine v3.0). Check that this cost applies to pitches breaking away as it should.
- **Something else** the measurements point to.

### 4. Build the mechanism the measurements support

One mechanism, measured from the league (for example, the read's noise or commit point as a function of the angle
between the release and the batter's line of sight, fitted to the league's same-side whiff and chase excess). Then run
the chain and the suite.

**Accept it** if the platoon split comes within the league's range (in the within-player measure) with no costs on the
suite. Also report K% against release height and BB% against arm angle. If the cause turns out to be a bug, fix it as
the rules say.
